# FLAT·SIX — Full-app offline (Desktop + PWA)

One product: the **Next.js garage** ships as **FLAT·SIX Desktop** (Electron) and an
installable **PWA**, with offline garage sync + curated knowledge. Workshop PDFs /
`manual_sections` / AI stay **online-only** in v1.

## Architecture

```
Next.js garage (app/) + lib/offline + lib/obd + lib/knowledge
        ↓
   PWA (service worker)     Electron apps/desktop
   (Vercel / Chrome)        (standalone Next + serialport)
```

| Offline | Online-only (v1) |
| --- | --- |
| App shell | Documents / PDFs |
| `lib/knowledge` TF search | `manual_sections` / Voyage |
| Garage CRUD (vehicles, records, plans) via IndexedDB sync | AI / MCP |
| Live OBD in Desktop (USB + Classic BT) | — |
| Live OBD in PWA desktop (Web Serial USB) | Classic BT on PWA |

## Offline data

- Wired through [`lib/db/*`](../../lib/db) — reads fall back to cache; writes queue when offline

## Desktop updates

Packaged Desktop uses [`electron-updater`](https://www.electron.build/auto-update)
with **GitHub Releases** (`dmitry-grechko/flat-six`). Owners on the **NSIS
installer** (Windows) or **DMG** (macOS) get background checks on launch, a banner
when an update is ready, and **Restart now** to apply. **Portable** Windows builds
do not auto-update — re-download from Releases.

### Owner experience

1. App starts → silent check against the latest GitHub Release (~3 s after launch).
2. New version → download in background; banner shows progress.
3. Download complete → **Restart now** or **Skip this version** (stored locally).
4. No network / no release yet → no banner.

### Maintainer release procedure

1. Bump `apps/desktop/package.json` `version` (semver).
2. Build: `npm run build` → `npm --prefix apps/desktop run prepare:standalone` →
   `npm --prefix apps/desktop run pack` (Win) / `pack:mac` (macOS).
3. Tag `vX.Y.Z` on `main` — CI builds and publishes:
   [`.github/workflows/desktop-release.yml`](../../.github/workflows/desktop-release.yml) (Desktop)
   and [`.github/workflows/bridge-release.yml`](../../.github/workflows/bridge-release.yml) (OBD Bridge zip).
   Or `workflow_dispatch` with **publish** checked for a one-off upload.
4. Assets must include `latest.yml` / `latest-mac.yml` (generated by
   electron-builder) plus installers — `electron-updater` reads these metadata files.
5. Set `href` / `hrefMac` in [`lib/downloads.ts`](../../lib/downloads.ts) for
   first-time installs; returning users update in-app.

### Channels (future)

Stable = default GitHub `release`. Beta = GitHub **prerelease** tag +
`autoUpdater.channel` (`beta`) in `main.mjs` when you split channels.

### Decisions before first public ship

| Topic | Current state | Recommendation |
| --- | --- | --- |
| **Code signing** | Win: `signAndEditExecutable: false`; Mac: `identity: null` | Sign Win (Authenticode) + Mac (Developer ID) for SmartScreen/Gatekeeper and smoother updates |
| **Update server** | GitHub Releases (configured in `apps/desktop/package.json` `publish`) | Keep — matches `REPO_URL` / Downloads page |
| **Portable Win** | Built alongside NSIS | Document manual re-download; auto-update NSIS only |
| **CI** | Typecheck only | Add release workflow with `GH_TOKEN` secret |

Implementation: `apps/desktop/main.mjs` (`autoUpdater`), `preload.cjs` (IPC),
[`lib/electron/updateClient.ts`](../../lib/electron/updateClient.ts),
[`components/shell/DesktopUpdateBanner.tsx`](../../components/shell/DesktopUpdateBanner.tsx).
